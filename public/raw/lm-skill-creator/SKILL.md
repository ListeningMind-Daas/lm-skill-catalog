# LM 스킬 크리에이터

> 만드는 것: 커넥터 1~3개로 **한 가지 질문에 답하고 정해진 산출물을 내는** 태스크 스킬.
> 만들지 않는 것: 온톨로지 · 버티컬 오버레이 · 오케스트레이션 계약.

## 0. 왜 골격을 사람이 쓰지 않는가

기존 카탈로그 12종을 스캔한 결과다.

| 데이터 함정 | 처리하는 스킬 |
|---|---|
| 데이터 기준월 · 조회 지연 | **0 / 12** |
| 절단(limit) 오독 | **0 / 12** |
| 브랜드/논브랜드 분리 | **0 / 12** |
| `volume_trend` 신뢰성 | 1 / 12 |
| 표기변형 정규화 | 3 / 12 |

**함정 처리가 저자 개인의 각성에 달려 있었다.** 그 함정들은 산출물이 정상적으로 완성되면서
결론만 틀리는 종류라, 리뷰로도 안 잡힌다. 그래서 이 스킬은 규율을 문장이 아니라
**골격·스크립트·감사기**로 강제한다.

## 1. 번들 자산

| 파일 | 하는 일 |
|---|---|
| `scripts/new_skill.py` | 골격 생성 — 계약·재사용 스크립트·템플릿 배치, 함정 의무를 ⬜로 박고 **의무 선언 블록**을 심음 |
| `scripts/audit_skill.py` | 정적 감사 — 계약 준수를 P0/P1/P2로 분류 (exit 1 = P0) |
| `scripts/selftest.py` | 크리에이터 자가검증 — 골격 생성·감사기 동작 회귀 검사 |
| `references/audit-rubric.md` | P0/P1/P2 분류 기준과 근거 |
| `references/themes-schema.md` | `themes.json` 스키마 — 분류·정규화를 쓰는 스킬이 반드시 읽는다 |
| `shared/lm-data-contract.md` | **데이터 계약 정본** |
| `shared/scripts/*.py` | **재사용 스크립트 정본** — 골격 생성 시 복사된다 |
| `shared/assets/themes.template.json` | 분류 사전 템플릿 |
| `shared/verify_shared.py` | 계약·스크립트·템플릿 사본 드리프트 해시 검사 |

> 명령 예시의 경로는 모두 **저장소 루트 기준**이다.
> **이 스킬은 저장소 전체(클론)에서 실행한다** — 골격 생성·자가검증이 루트의 `shared/` 정본을 읽어
> 사본을 만들기 때문이다. 이 폴더만 따로 복사하면 `new_skill.py`·`selftest.py`가 동작하지 않는다.
> 만들어진 태스크 스킬은 반대로 자기 폴더만으로 동작한다.

## 2. 실행 순서

### STEP 0 · 무엇을 만드는지 확정

라우팅부터 확인한다(온톨로지·오버레이·오케스트레이션이면 여기가 아니다). 그 다음 5개 변수:

| 변수 | 결정하는 것 |
|---|---|
| **잡** | 한 문장 정의. "무엇을 입력받아 무엇을 답하는가" |
| **커넥터 조합** | 예산식과 한계. 최소 조합으로 — `path_finder`는 최고가다 |
| **시계열 사용 여부** | T1·T2·T3·T4·T6 처리 의무 발생 |
| **반복 확장 여부** | T7(절단) 처리 의무 발생 |
| **점유·기회 논의 여부** | T8(논브랜드) 처리 의무 발생 |

### STEP 1 · 골격 생성

```bash
python3 skills/lm-skill-creator/scripts/new_skill.py <스킬명> --job "한 줄 정의" \
    --connectors keyword_info,intent_finder --monthly --expand --share
```

계약 사본·재사용 스크립트·분류 템플릿·eval 스텁이 배치되고, **해당 함정이 ⬜로 SKILL.md에
박힌다.** ⬜가 남아 있으면 감사가 P0로 막으므로 빠뜨릴 수 없다.

같이 심기는 **의무 선언 블록**이 감사의 기준이 된다:

```
<!-- lm-skill: kind=task; connectors=keyword_info,intent_finder; flags=monthly,expand,share; traps=T1,…,T8 -->
```

감사기가 문서 문구로 의무를 추론하면 "이 커넥터는 쓰지 마라" 같은 문장까지 잡힌다.
그래서 **스킬이 스스로 선언하고 감사기는 그것을 기준으로 검사한다.** 선언이 없는 레거시
스킬은 추론으로 감사하되 P2로 표시된다.

**공유 자산이 없으면 생성이 중단된다.** 빈 스크립트로 스킬이 나가는 것을 막기 위해서다.

### STEP 2 · 내용 채우기

⬜를 채운다. 채울 때 지키는 것:

- **description**은 트리거 발화를 인용으로 넣는다. 언더트리거가 기본값이므로 조금 밀어붙인다.
- **크레딧은 결정식**으로 적는다. 관측 범위(`58~208`)를 상한처럼 적지 않는다.
- `keyword_info`를 쓰면 **2단 조회**를 기본으로 — 전량 `ads_metrics`(1) → 게이트 통과분만 `all`(10).
  2단 대상 수가 총액을 지배한다.
- **산출물 컬럼 목록 = 스크립트 실제 출력.** 어긋나면 문서를 믿은 쪽이 틀린 산출물을 만든다.
- 함정 처리는 **어느 STEP에서 어떻게** 하는지까지 쓴다. 이름만 적는 것은 처리가 아니다
  (감사기는 의무 표를 빼고 본문만 본다).

### STEP 3 · 자가검증

```bash
cd <스킬폴더> && python3 scripts/selftest.py
```

합성 픽스처로 **문서의 예시 명령을 실행**한다. API·크레딧 불필요.
셸 프로세스 치환 같은 우회로 대신 확인하지 않는다 — 그 우회가 실제로 결함을 놓친 적이 있다.

### STEP 4 · 정적 감사

```bash
python3 skills/lm-skill-creator/scripts/audit_skill.py <스킬폴더> \
    --contract shared/lm-data-contract.md
python3 shared/verify_shared.py        # 계약·스크립트 사본이 정본과 같은가
```

P0가 하나라도 있으면 배포하지 않는다. 분류 기준은 `references/audit-rubric.md`.

### STEP 5 · 실행 평가 (크레딧 소모)

감사는 문서를 보고, 평가는 **실제로 돌려본다.** 정적 감사가 통과해도 실행에서 결함이 나온다
— 실제로 이 키트의 스킬들도 정적 감사를 통과한 뒤 실행 평가에서 새 결함이 나왔다.

1. eval 2케이스 이상 — **함정을 밟는 카테고리**를 고른다
   (계절 역위상 · 시드 미제공 · 표기변형이 심한 카테고리 · 브랜드 지배 카테고리)
2. 두 구성을 같은 예산으로 실행 — 신규 스킬이면 «스킬 없음», 개정이면 «이전 버전»
3. 채점 항목은 **함정 의무와 1:1**로 만든다. 변별력 없는 항목(양쪽 다 통과)도 하나 남겨
   회귀 감지용 대조군으로 쓴다
4. 산출물을 사람이 본다. 정량 통과율만으로 판단하지 않는다

### STEP 6 · 개선 루프

```
감사·평가 → 결함을 P0/P1/P2로 분류 → 조치 → 재평가
```

- **P0만 즉시 반영**한다. P1·P2는 목록으로 남기고 다음 버전에서 묶는다.
- `CHANGELOG.md`에 **결함과 근거 수치**를 같이 적는다. "개선함"이 아니라 "무엇이 몇 % 틀렸다".
- **통과했다고 결함이 없는 게 아니다.** 새 결함이 나오면 그것도 이력에 남기고, 재발 유형이면
  규칙이 아니라 **검사 수단**을 만든다(예: 명세-코드 불일치가 두 번 반복돼 `selftest.py`가 생겼다).
- 규칙이 자기 자신에게 소급 적용되는지 확인한다 — 새 규칙이 기존 산출물을 뒤집으면 그 산출물을 정정한다.

### STEP 7 · 공개 패키징

1. 변경 이력은 SKILL.md가 아니라 같은 폴더 `CHANGELOG.md`에 — SKILL.md는 절차에 집중하고, 판 번호는 frontmatter `metadata.version`
2. `README.md` 작성 — 무엇이 나오는가 / 설치 / 사용법 / **다루는 함정** / 크레딧 / 한계 / 기여 규칙
3. 누출 검사: 내부 경로·엔드포인트·키 파일 경로·익명 예시(`brand-a`)
4. 예시를 **공개 가능한 실제 카테고리**로 교체 — 익명 예시는 무엇이 좋은 입력인지 못 가르친다
5. `license` 확인 — 이 저장소 표준은 **MIT**(루트 `LICENSE`)
6. `shared/verify_shared.py`로 계약·스크립트 사본 동기 확인

## 3. 완료 게이트

완료에는 두 단계가 있다. **STEP 0~4까지는 «작성 완료»일 뿐 «완료»가 아니다** —
정적 감사는 문서에 처리가 적혀 있는지만 보고, 적힌 처리가 옳은지·실제로 도는지는 못 본다.

| 상태 | 조건 | 크레딧 |
|---|---|---|
| **작성 완료** | 감사 P0 0 + selftest 통과 + 공유 자산 동기 | 0 |
| **검증 완료** | 위 + eval 실행 + 사람이 산출물 확인 | 소모 |

배포는 «검증 완료»에서만 한다.

- [ ] `audit_skill.py` P0 0건
- [ ] `selftest.py` 통과
- [ ] eval 2케이스 이상 실행 + 사람이 산출물 확인
- [ ] 함정 의무 전건에 «어느 STEP에서 어떻게»가 적혀 있음
- [ ] 산출물 컬럼 목록 = 스크립트 실제 출력
- [ ] 크레딧이 결정식으로 적혀 있고 2단 조회가 반영됨
- [ ] 계약 사본이 정본과 동일 해시
- [ ] `license` MIT 확인 · 누출 검사 통과
- [ ] 의무 선언 블록 존재

## 4. 카탈로그 재생성

기존 스킬을 이 계약으로 옮길 때:

1. `audit_skill.py`를 **전 스킬에 일괄** 돌려 P0 목록을 뽑는다
2. P0가 많은 순이 아니라 **사용 빈도가 높은 순**으로 고친다 — 틀린 답이 많이 나가는 쪽이 급하다
3. 스킬마다 실행 평가를 붙인다. 정적 감사만으로 재생성했다고 하지 않는다
4. 재생성 전후를 같은 eval로 비교해 **회귀가 없는지** 확인한다
