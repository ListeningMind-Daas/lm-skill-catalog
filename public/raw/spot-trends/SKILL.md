# Spot Trends — 초기 트렌드 신호 포착

> **핵심 원칙**: 트렌드는 검색량이 아니라 **변화율의 변화**다. 그리고 계절 카테고리에서
> 변화율을 직전 기간 대비로 재면, 잡히는 것은 트렌드가 아니라 **계절**이다.

## 사전 확인

```
1. 분석 시장(gl)이 단일 값으로 확정되었는가? — issue_list 인덱스도 국가별이다
2. 시드 키워드가 하나로 정해졌는가? (issue_list의 keyword는 단일 문자열) · 사용자가 준 후보 목록이 있는가?
   — 있으면 그 목록이 후보이고 trend_finder는 근거로만 붙인다. 없으면 STEP 1이 후보를 만든다
   — 시드에 띄어쓰기가 있는가? 띄어쓴 시드는 단어 하나만 맞아도 이슈를 가져온다(실측: «캠핑 의자» 매칭 147건 ·
     반환 50건 중 의자 관련 1건 · 범위 밖 39건을 거르면 11건 / «캠핑의자» 1건). 붙여 쓴 형태도 부를지 사용자와 정한다(호출당 상한 50 + 2 × limit)
2-1. 카테고리 경계를 확인했는가? — 동음이의·다른 업권이 섞였는지 (STEP 2)
3. 후보군이 몇 개인가? — 확산 폭은 후보군 안에서 계산되므로 50개 미만이면 확산 폭을 약한 근거로 적는다
   (issue_list limit 50이면 병합 뒤 50개보다 적다. 사용자 후보나 map-your-market 유니버스를 합치면 커진다)
4. 시계열이 24개월 이상 확보되는가? — 전년 동기 비교에 최소 15개월,
   가속도(창 2개 비교)에 최소 18개월이 필요하다
```

## 예산 (결정식 · 호출 전에 사용자에게 제시)

```
trend_finder  = 50 × 결과가 있는 호출 수 + 2 × 반환 이슈 수   # 빈 결과 호출은 0 (2026-09-29 실측 · 계약 §1)
                호출 전 상한은 호출마다 50 + 2 × limit        # 결과가 있을지 미리 모르므로 상한으로 잡는다
keyword_info  = 1 × N (ads_metrics 스크린) + 10 × M (all — 스크린 통과분)
합계 상한     = (50 + 2 × limit) × C + N + 10 × M

C = 1 (14일에 범위 안 이슈가 있으면) · 2 (없으면 → 90일) · 3 (90일도 없으면 → 선택적으로 365일)
    · 띄어쓴 시드를 붙여 쓴 형태로도 부르면 +1
N = 병합 후 후보 수 + 시드 1 (≤ 반환 이슈 + 사용자 후보 + 1)  ·  M ≤ N
```

상한 예시(시드 1 · limit 50 · 사용자 후보 없음 · 넓히지 않음): 150 + 51 + 10 × 51 = **711**.
365일까지 넓히면 150 × 3 + 51 + 510 = 1,011이 상한이다(빈 결과 호출은 실제로 0이라 실소비는 이보다 작다).
실소비는 응답 `cost_detail.total_cost` 합이 유일한 기준이다 — `issue_candidates.py`가 결정식(빈 호출 0)과
`cost_detail` 합을 한 줄로 대조하고 어긋날 때만 «환경 단가 확인»을 띄운다. 이 줄은 알림 «수집 사실»에도 옮겨진다.
사용자 후보를 쓰면 N이 그만큼 늘고, 후보를 스크린 없이 곧장 `all`로 보내면 `keyword_info = 10 × N`이다.

## STEP 1 · 이슈 후보 (trend_finder)

```python
trend_finder_issue_list(keyword=seed, gl="kr", period_days=14, limit=50, sort="score", order="desc")
# 결과가 있으면 50 + 2 × 반환 · 빈 결과면 0 · keyword는 단일 시드(배열 아님) · 응답을 파일로 저장한다 (tf_14d.json)
```

```bash
python3 scripts/issue_candidates.py tf_14d.json [tf_90d.json] -o candidates.json \
    --evidence-out issue_evidence.csv [--meta-out issue_meta.json] [--rules '{"썬":"선"}'] \
    [--exclude '<범위 밖 정규식>'] [--user-candidates mine.json] [--no-seed]
```

- **빈 결과는 실측이다**(«그 기간 매칭 없음»). 넓힘은 **범위 안 이슈 수**(`--exclude`로 거른 뒤)로 판정한다 —
  응답이 비었든, 반환은 있지만 전부 범위 밖이든 범위 안 이슈가 0이고 가장 넓은 기간이 90일 미만이면 exit 3으로 멈추고
  `period_days=90`으로 **한 번** 더 조회하라고 알려 준다. 90일도 0이면 «이슈 없음»으로 결론 낸다(365일은 선택 —
  호출 상한 50 + 2 × limit · 빈 결과면 0). 이슈를 지어내지 않는다. «14일 0건 → 90일 N건» 사실은 알림에 옮겨진다.
- **띄어쓴 시드**(«캠핑 의자»)는 단어 하나만 맞아도 이슈를 가져온다(계약 §1). 스크립트가 경고하고 붙여 쓴 형태
  («캠핑의자») 조회를 비용과 함께 제안한다. 반환 건수가 많아도 범위 안 이슈가 적을 수 있다 — 결론은 범위 안 건수로 낸다.
- 후보는 **시드 자체**(맨 앞 · `--no-seed`로 뺀다) + `data[].keyword`(범위 밖 제외) + 사용자 후보다.
  시드를 넣는 이유: 시드의 전년 동기 추세가 후보들의 비교 기준이 되고, 이슈가 하나도 없을 때도 «시드 자체가 오르는가»에는 답한다.
- `series_dedup.canon`(+`--rules`)으로 표기변형·반복 항목을 한 후보로 합친다 `[추정]`. 모델명은 표기가 갈라진다
  (실측: 같은 러닝화 모델이 6가지 표기로 와서 후보 6개가 됐다) — `--rules`에 치환 쌍을 준다(인라인 JSON · 파일 ·
  themes.json의 `rules.변형치환`). 치환은 공백을 지우기 전에 순서대로 적용되므로 공백 차이를 먼저 맞추는 쌍을 앞에 둔다:
  `{"플라이 3":"플라이3","나이키 알파플라이3":"알파플라이3","알파 플라이3":"알파플라이3"}`.
  같은 `--rules`를 STEP 3 스크린과 STEP 5 `trend_signals.py`에도 준다.
- 후보마다 근거를 남긴다: 최고 `issue_score` · `content_type` · `topic` · `index_date` 분포(여러 날짜에 반복 = 지속) ·
  `summary`(AI 생성 요약 — `[추정]`) · `source_links` 앞 3개. `source_checked`는 빈칸으로 나온다 —
  출처 원문을 열어 확인한 문장만 거기에 적고, 그 문장만 `[실제 데이터]`로 인용한다.
- `total` > 반환 수이면 «limit 절단» 경고가 뜬다(T7) — 후보가 전부가 아니라는 뜻이다. 알림 «수집 사실»에 옮겨진다.
- `issue_meta.json`에 호출별 반환·범위 안·total·limit·cost_detail, 넓힘·절단·띄어쓰기 메모, 크레딧 대조 줄, 범위 밖 목록,
  시드 포함 여부가 남는다. STEP 3 스크린이 여기에 결과를 덧붙이고, STEP 5·8이 읽는다.
- 기간은 응답 `request_detail.period_days`에서 읽는다. 없으면 `tf.json@90`처럼 붙인다.
- 사용자가 후보 목록을 주면 `--user-candidates`로 합친다. 이때 trend_finder는 선택이고, 부른다면 근거로만 쓴다.
- 인덱스는 **구글** 자동완성·검색결과 기반이다. 네이버 비중이 큰 시장에서 «국내 이슈 전체»라고 쓰지 않는다.

## STEP 2 · 후보 범위 점검 (keyword_info 크레딧 쓰기 전)

후보군을 훑어 **카테고리 밖 키워드**를 먼저 뺀다. 한 단어가 여러 뜻이면 후보가 섞인다 — 실측(2026-09-28):
«러닝» 연관 키워드 80개 중 24개(30%)가 e러닝·머신러닝·딥러닝처럼 운동 러닝이 아니었다. 이슈 후보도 마찬가지다
(실측 2026-09-29: «캠핑 의자» 이슈 50건 중 39건이 캠핑장·차박 차량·방송 사건 등 범위 밖).
뺄 패턴을 사용자에게 보여 주고 확인받은 뒤 **STEP 1 명령을 `--exclude '<정규식>'`으로 다시 돌린다**(0크레딧) —
후보에서 빠지고, 넓힘 판정이 범위 안 건수로 다시 계산되고, 정규식이 `issue_meta.json`에 남아
`trend_signals.py`가 그 후보를 «범위 밖 제외»로 센다(«검색량 미반환»으로 새지 않는다). 호출 뒤에 발견하면
`trend_signals.py --exclude '<정규식>'`으로 스코어링에서 뺀다(이미 쓴 크레딧은 돌아오지 않는다).

## STEP 3 · 시계열 확보

```python
keyword_info(keywords=candidates, gl="kr", data_type="ads_metrics")   # 1 × N — 스크린
```
```bash
python3 scripts/issue_candidates.py --screen ads_metrics.json --candidates candidates.json \
    --gate 3000 --window 3 -o all_candidates.json --meta issue_meta.json [--rules …]
```
```python
keyword_info(keywords=all_candidates, gl="kr", data_type="all")       # 10 × M — 판정 대상만
```

스크린은 `volume_avg × window ≥ gate` `[가정]`이다(`volume_avg` = 최신 3개월 평균, 계약 §2). 판정 게이트는 STEP 5에서
전년 동기 창에 다시 걸린다 — 스크린은 비용을 줄이는 1차 거름이지 판정이 아니다. 스크린 미달·미반환 후보는
**버리지 않는다** — STEP 7에서 사유별로 남는다: 스크린 탈락은 볼륨이 측정된 것이라 `volume_avg`와 함께
«스크린 탈락», ads_metrics 응답에 행이 없던 것만 «검색량 미반환».

스크린은 후보를 **묶고 병합한다** `[추정]`: 같은 canonical(`--rules` 치환 포함)로 온 응답 행은 한 후보의 표기변형으로 묶어
`volume_avg` 하한(최댓값) ~ 상한(같은 검색은 한 번만 센 합)을 출력하고, `all`에는 **측정된 표기 중 `volume_avg`가 가장 큰 것**을 보낸다.
서로 다른 후보라도 지표(volume_total·CPC·경쟁도·gg/nv)가 모두 같고 토큰이 겹치면 `series_dedup.dedup_map`이 같은 검색으로 보고
«같은 검색 병합»으로 한 번만 보낸다(10크레딧씩 아낀다). 묶음·병합은 출력과 알림 «수집 사실»에 남는다.
ads_metrics `cost_detail`이 후보 수와 다르면 요청 목록이 `candidates.json`과 달랐다는 뜻이라 경고한다.

`monthly_volume`이 필요하므로 판정 대상에는 `all`을 쓴다. `ads_metrics`(1/kw)에는 시계열이 없다.
`ads_info`는 쓰지 않는다 — `monthly_volume`을 주지만 단가가 환경마다 다르게 관측됐고(10 · 1)
`all`이 상위집합이다(계약 §1). `all`로 통일하면 환경마다 단가를 확인할 필요가 없다.

과금은 **요청한 키워드 수**다. 응답에서 빠진 키워드도 과금되고, 요청하지 않은 표기변형은 무과금으로 함께 온다.
`--requested all_candidates.json`(실제로 `all`에 요청한 목록)을 주면 빠진 키워드를 `[데이터 공백]` 미반환 목록으로 출력한다.

**후보군을 그대로 다 `all`에 넣지 않는다.** 10크레딧/kw이므로 M이 곧 예산이다.
`map-your-market` 산출물이 입력이면 **볼륨 상위 N + 논브랜드 축**으로 먼저 추린다.

## STEP 4 · 데이터 기준월 확인 ⚠️ 생략 금지

```bash
python3 scripts/check_refmonth.py <응답.json> --queried-at YYYY-MM-DD
```

리포트 헤더에 **`데이터 기준월 / 조회일 / 지연`** 세 값을 적는다. 기준월은 응답에서 읽는다
(`monthly_volume`의 `month` 최댓값 — 배열 순서를 가정하지 않는다). 관측 지연은 1개월이었다(2026-09-28 조회 → 2026-08).

트렌드 스킬에서 이것이 특히 치명적인 이유 — 조회일을 데이터 시점으로 착각하면
**"몇 개월 빠른 신호"라는 주장 자체가 성립하지 않는다.** 지연이 N개월인데 그 위에서 6개월 앞을 말하면,
실제로는 6 − N개월이다. 마지막 달 제외(기본)까지 더하면 계산 창은 기준월보다 한 달 더 이르다.

같은 명령이 **마지막 달 완결성**도 검사한다. 의심 건수를 리포트에 적는다.

## STEP 5 · 4지표 스코어링

```bash
python3 scripts/trend_signals.py <응답.json> -o trend_signals.csv \
    --gate 3000 --rules '{"썬":"선"}' --requested all_candidates.json --evidence issue_evidence.csv \
    --issue-meta issue_meta.json
```

`--evidence`를 주면 이슈 근거(`issue_*` 컬럼)를 canonical로 신호 행에 붙이고,
검색량으로 판정하지 못한 후보를 `<출력>_issue_only.csv`에 따로 쓴다(STEP 7). `--issue-meta`를 주면 스크린 결과로
사유를 가르고(스크린 탈락 · 미반환 · 같은 검색 병합), `--exclude`가 없을 때 STEP 2의 범위 밖 정규식을 읽어 쓴다.

네 지표를 **모두 전년 동월 대비로** 계산한다. 이것이 계절 위양성을 막는 유일한 방법이다.

| 지표 | 계산 | 왜 이렇게 |
|---|---|---|
| **성장률** | 최근 W개월 합 ÷ 전년 같은 W개월 합 − 1 (기본 W = 3) | 직전 기간 대비로 재면 성수기 진입이 곧 성장으로 잡힌다 |
| **가속도** | 최근 창의 성장률 − 직전 창의 성장률. CSV `accel`은 비율 차이(0.25)이고 리포트에는 **%p**(+25%p)로 적는다 — «%»로 쓰면 성장률로 오독된다 | **전년 대비끼리의 차** — 계절이 양쪽에서 상쇄된 2차 미분 |
| **지속성** | 기준월부터 «전년 동월 대비 상승»이 이어진 개월 수 | 단발 스파이크와 추세를 가른다 |
| **확산 폭** | 띄어쓰기 토큰을 공유하는 다른 키워드 중 함께 상승한 비율 | 혼자 오르는가, 무리 지어 오르는가 |

**등급은 두 관문을 모두 넘어야 붙는다.**
1. **절대 하한**(`--min-growth`, 기본 0 `[가정]`): 성장률이 0 이하면 점수와 무관하게 등급을 주지 않는다
   (`grade_floor` = «하한 미달»). 마지막 달 포함 모드면 **마지막 달 제외 기준 성장률**도 0을 넘어야 한다.
   백분위만 쓰면 후보군 전체가 하락할 때 하락 키워드에도 등급이 붙는다(실측: 롱패딩 −10%에 B, 선스틱 −4%에 B).
2. **백분위 점수** = 성장률 35% + 가속도 35% + 지속성 15% + 확산 15%, S(≥0.85) · A(≥0.70) · B(≥0.55) `[가정]`.
   **판정 행이 10행(`--abs-pool`) `[가정]` 미만이면 백분위 대신 절대 기준**으로 매긴다 — 백분위는 «자기보다 작은 값의 비율»이라
   1행이면 최고 점수가 0.15(지속성 몫)뿐이다. 실측(2026-09-29): «가벼운 청소기» 성장률 +51%·가속도 +58%p·지속 4개월,
   «호카 본디 9» +57%·지속 12개월·전년 창 147,400건이 1행 풀에서 «등급 없음»이었다. trend_finder 경로는 작은 풀이 보통이다.
   절대 기준 `[가정]`: **S** 성장률 ≥ 50% · 지속 ≥ 6개월 · 가속도 ≥ 0 / **A** ≥ 30% · ≥ 3개월 · 가속도 > −20%p(빈칸 허용) /
   **B** ≥ 15% · ≥ 2개월. 가속도가 빈칸(직전 창 게이트 미달)이면 S는 주지 않는다. 절대 하한(①)은 그대로 먼저 건다.
   어느 기준으로 매겼는지 `grade_basis`에 남고(`백분위` · `절대 기준(판정 N행 < 10)`), 알림 헤더에 기준이 적힌다.

**기저 게이트**(`--gate`, 기본 3,000): 전년 동기 볼륨이 이 값 미만이면 랭킹에서 제외한다(`gated_out` = 게이트 미달).
없으면 22건 → 57,772건 같은 키워드가 `+262,500%`로 1위에 올라온다. 성장률이 아니라 기저가 0이었던 것이다.
**가속도에도 같은 게이트를 건다** — 직전 창의 전년 볼륨이 게이트 미만이면 가속도를 비우고
`accel_note` = «직전 창 게이트 미달»로 남긴다(게이트가 없으면 직전 창 기저가 작아 가속도 −3,381%p·−23,229%p가 점수에 들어간다 — 실측).

**결측 월**: 비교 창에 결측(`nv_code`)이 하나라도 있거나 전년 창이 0이면 «계산 불가»로 남긴다(`gated_out` = 계산 불가).
0으로 합산하지 않는다 — 조용한 과소집계가 곧 가짜 하락 신호가 된다.
`gated_out`의 값은 세 가지다: `게이트 미달` · `계산 불가` · `같은 검색의 중복`(STEP 6).
게이트 미달이나 전년 동기 0(계산 불가)인데 최근 창 볼륨이 측정된 행은 알림의 **«신생·저기저 급등 후보»** 절로 간다(STEP 7).

### 판정 풀이 작을 때 — 비수기 계절 품목

3개월 창의 전년 볼륨이 작으면(겨울 품목을 여름에 보는 경우) 대부분이 게이트에 걸린다. 실측: 롱패딩 81행 중
판정 9행(게이트 미달 70). 스크립트는 판정 행이 20행 또는 전체의 25% `[가정]`보다 적으면 `⚠️ 판정 풀이 작다`를
띄우고(알림 헤더에도 같은 경고가 들어간다) **`--window 12`로 다시 계산하면 몇 행이 판정되는지**를 함께 출력한다(같은 응답 · 0크레딧 — 롱패딩은 77행).
12개월 창 성장률은 계절 한 바퀴를 덮으므로 «최근 1년이 전년보다 컸나»를 본다 — 3개월 창보다 늦게 반응한다는 점을
리포트에 적는다.

### 마지막 달은 기본적으로 제외한다

`trend_signals.py`는 **마지막 달을 빼고** 계산한다(`--include-last-month`로 주 모드를 뒤집을 수 있다).
어느 쪽이든 스크립트는 **두 모드를 모두 계산**해, 등급이나 성장률 부호가 모드에 따라 달라지는 행에
`provisional` = «잠정»을 달고 다른 모드의 등급을 `grade_other_mode`에 남긴다(수작업 비교 불필요).

마지막 달은 집계가 아직 차는 중일 수 있고(관측 사례: 하루 뒤 27,100 → 65,800),
**가속도와 지속성이 거기에 가장 민감하다.**

> **실측** — 선크림 KR 357키워드에서 두 모드를 비교했더니
> **등급이 붙은 키워드의 64%(49/77)에서 등급이 달라졌고, 49건은 성장률 부호가 뒤집혔다.**
> 예: `넛세린 선스틱` 제외 시 A(+267%) → 포함 시 무등급(+115%).
>
> **트레이드오프**: 한 달 늦게 본다. 대신 부호가 뒤집히지 않는다.
> 속도를 택하려면 `--include-last-month`를 쓰되 **리포트에 반드시 명시**하고,
> «잠정» 표시를 그대로 옮긴다.

## STEP 6 · 표기변형 정규화

`--rules`로 치환 쌍을 넘긴다(인라인 JSON 또는 파일). API가 요청하지 않은 표기변형을
함께 반환하므로, 정규화 없이 확산 폭을 계산하면 **같은 키워드가 서로의 확산 근거가 된다**
(`선크림`과 `썬크림`이 서로를 "함께 오른 이웃"으로 세는 문제).

`canonical` 컬럼으로 그룹키를 남기되 행은 보존한다. 치환은 띄어쓰기를 지우기 전에 적용된다(단어 경계 보존).

**같은 검색의 중복**(계약 T5 ①): 시계열이 완전히 같은 행은 어순·표기가 달라도 같은 검색을 두 번 받은 것이다.
`dup_of`에 대표 키워드를 적고 `gated_out` = «같은 검색의 중복»으로 랭킹에서 뺀다 — 대표 행에서 한 번만 판정한다.

**확산 폭의 이웃**: 띄어쓰기를 살린 토큰으로 잇는다(`토코보 선스틱` → {토코보, 선스틱}). 공백을 지운
canonical을 쪼개면 한국어 키워드마다 토큰이 하나뿐이라, 같은 canonical을 이웃에서 빼는 순간 **확산 폭이 전 행 공백**이 된다
(실측: 3개 카테고리 222행 중 0행). 이웃에서는 같은 canonical 그룹과 같은 검색의 중복 묶음을 뺀다 — 변형끼리 서로의 확산
근거가 되지 않는다. 행의 절반 이상이 공유하는 **머리 토큰**(`선스틱`) `[가정]`은 다른 토큰으로 이웃을 못 찾을 때만
쓴다 — 머리 토큰만으로 이으면 확산 폭이 «카테고리 전체 상승 비율» 하나로 뭉개진다.

4지표와 등급은 **행 단위**다. 같은 그룹의 변형 행이 둘 다 등급을 받으면 리포트에서는 한 신호로
묶어 적는다. 그룹 규모를 말할 때는 한 값을 쓰지 않는다 — 변형 행이 같은 검색의 중복인지 서로 다른
검색인지 응답이 알려주지 않으므로(계약 T5 ②), 스크립트는 전년 동기 창 볼륨을 **그룹마다**
`하한 X ~ 상한 Y`(하한 = 그룹 내 최댓값 · 상한 = 그룹 내 합, `[추정]` 규칙 기반 집계)로 출력하고
CSV의 `group_prev_year_lo`·`group_prev_year_hi`에 남긴다. 같은 검색의 중복 행은 합에 한 번만 들어간다.
규모 서술은 하한 기준으로 하고 상한을 병기하며, 두 기준에서 결론이 뒤집히면 그 사실을 적는다.
기저 게이트(`--gate`)는 행 단위 전년 동기 볼륨에 걸린다 — 그룹 합으로 통과시키지 않는다.

## STEP 7 · 교차확인과 해석

- 상위 신호 몇 건을 `trend_yoy.py`로 다시 계산해 값이 일치하는지 확인한다
- **`volume_trend` 필드는 판정에 쓰지 않는다.** 실측에서 검증 YoY와 부호가 38~75% 어긋났다
- 신호가 **왜** 생겼는지는 검색량이 답하지 못한다. 이슈 근거(`issue_summary_ai`·`issue_sources`)는 원인 **가설**이다 —
  요약은 AI 생성이라 `[추정]`, 출처 원문을 열어 확인한 문장(`issue_source_checked`)만 `[실제 데이터]`. 인과로 단정하지 않는다
- 여러 `index_date`에 반복된 이슈(`issue_n_dates` ≥ 2)는 단발이 아니라 지속 이슈일 가능성이 있다 `[추정]` — 검색량 지속성과 별개다

### 신생·저기저 급등 후보 — 검색량은 있지만 기저가 작다

게이트 미달이거나 전년 동기 창이 0(계산 불가)인데 **최근 창 볼륨이 측정된** 행은 «검색량 미확인»이 아니다.
알림은 이 행들을 **«신생·저기저 급등 후보 (기저가 게이트 미만 — 성장률은 참고)»** 절에 따로 싣는다:
최근 창 · 전년 동기 창 · 최신 월 볼륨 · 검색 시작 월(`first_active_month`) · 성장률(참고) · 이슈 점수. **등급은 주지 않는다** —
기저가 작으면 성장률이 기저 효과로 부푼다. «신생 키워드 감지» 요청은 이 절이 답한다. 실측(2026-09-29, 러닝화·캠핑 의자):
최근 창이 전년 창 1,980 → 143,650건인 모델, 220 → 5,090건인 모델, 전년 0에서 2026-05부터 월 3천 건대로 검색된 신제품이
이 절에 해당한다 — «검색량 미확인»으로 적으면 틀린다. 구분은 `기저 게이트 미달` · `전년 동기 0 — 신생`(결측 월 수 병기)이다.

### 이슈 신호만 · 검색량 미확인 — 버리지 않고 따로 적는다

trend_finder가 잡은 후보(와 스크린에서 멈춘 시드·사용자 후보) 가운데 검색량으로 판정하지 못한 것은
`<출력>_issue_only.csv`에 **사유와 함께** 남는다. **등급을 주지 않는다.** 이슈는 검색량이 아니고, 판정은 검색량만 한다.

| `reason` | 뜻 | 알림 |
|---|---|---|
| `스크린 탈락` | ads_metrics로 **볼륨이 측정됐지만** `volume_avg × window < gate`라 `all`을 사지 않았다 — `volume_avg` 병기 | 미확인 절 |
| `검색량 미반환` | ads_metrics(또는 `all`) 응답에 행이 없었다 `[데이터 공백]` | 미확인 절 |
| `같은 검색 병합 → X` | 스크린에서 X와 지표가 같아 한 번만 보냈다 `[추정]` | 미확인 절 |
| `시계열 없음` | 응답 행은 있지만 `monthly_volume`이 없다(`ads_metrics`만 받음) `[데이터 공백]` | 미확인 절 |
| `계산 불가` | 결측 월 — 전년 창·최근 창 어느 쪽이든 | 전년 0·최근 볼륨 있음이면 신생·저기저 절, 아니면 미확인 절 |
| `게이트 미달` | 전년 동기 창 < gate — 볼륨은 측정됨 | 신생·저기저 절 |
| `범위 밖 제외` | STEP 2 `--exclude`로 뺐다 | 표에 싣지 않고 건수·목록만(«수집 사실») |

`after_ref_month` = «예»는 마지막 인덱스일이 데이터 기준월보다 늦다는 뜻이다 — 그 이슈 기간의 검색량은 아직 월간 집계에 없다.
**재판정 날짜가 아니다**: 조회 기간이 14일이면 거의 모든 이슈가 «예»이고, 이슈 문자열이 검색어가 아닐 수 있어(사건명·인물명)
다음 기준월에 판정된다는 보장도 없다. 알림은 이 뜻과 «예» 건수를 한 줄로 적는다.

## 한계

- **월 그레인 · 기준월은 응답에서 읽는다(관측 1개월).** "N개월 빠른 포착"을 말할 때 지연을 빼고 말하지 않는다
- 최소 15개월(가속도는 18개월) 시계열이 필요하다 — 신생 키워드는 지표가 안 나온다. 대신 «신생·저기저 급등 후보» 절에
  측정 볼륨과 검색 시작 월을 싣는다(등급 없음 · 성장률은 참고)
- 판정 행이 10행 미만이면 등급은 절대 기준 `[가정]`이다 — 후보군 안의 상대 순위가 아니다
- 띄어쓴 시드는 단어 하나만 맞아도 이슈를 가져온다 — 반환 건수가 아니라 범위 안 건수로 판단한다
- 확산 폭은 **후보군 안에서만** 계산된다. 후보군이 편향되면 확산도 편향된다
- 검색은 관심 신호이지 구매가 아니다. 신호가 매출로 이어진다는 보장은 없다
- 원인을 판정하지 않는다 — 이슈 근거는 원인 가설이다(요약은 `[추정]`, 인과 단정 금지)
- **이슈는 검색량이 아니다.** `issue_list`에는 검색량이 없다. 등급·순위는 `keyword_info` 검색량으로만 매긴다
- 이슈 인덱스는 **구글** 자동완성·검색결과 기반이고 실시간 크롤이 아니다. 네이버 비중이 큰 시장(예: 한국)에서
  «국내 이슈 전체»로 단정하지 않는다 — 필요하면 `ads_metrics`의 gg/nv 비율을 함께 적는다
- 최근 이슈는 월 그레인 지연 때문에 검색량에 아직 안 보인다 — «이슈 신호만 · 검색량 미확인»은 «안 뜬다»가 아니라 «아직 모른다»다
- `issue_list` `limit` 절단이면 후보가 전부가 아니다 — 절단 경고를 산출물에 옮긴다
