에이전트에 ListeningMind API 연결 — 산출물 예시

사용자 질의: «내 에이전트에 LM API 연결해줘» · 스킬 plug-into-your-ai-agents v0.3.1 명세 v0.0.60 (잠금 파일 · 2026-09-29 동기화) · 시장 kr · 1회 상한 1,000 · 세션 예산 5,000 크레딧 (예시값) 모의 응답으로만 검증했다 — 실제 API 호출 0건 · 크레딧 0. 아래 수치는 연결이 도는지 보이는 모의 값이지 시장 분석 결과가 아니다.

1. 무엇을 만들었나

분석 리포트가 아니라 에이전트가 LM API를 안전하게 부르게 하는 연결 한 벌이다.

산출물 내용
tools.claude.json Claude tool use 도구 정의 9종 (name · description · input_schema)
tools.openai.json OpenAI function calling 도구 정의 9종 (type: function)
system_rules.txt 에이전트 시스템 프롬프트에 붙일 사용 규칙 10줄
dispatcher_example.py 두 프레임워크의 도구 호출 루프에 끼우는 디스패처 예 — 스킬 런타임 + 1회 상한 · 시장 고정
ledger.jsonl 크레딧 원장 — 호출 1건 = 1행 (22행)

tools.csv 도구 목록 한 장 (이 보고서 2절과 같은 내용)

2. 도구 목록

도구 엔드포인트 용도 크레딧 결정식 필수 인자
lm_cluster_finder POST /cluster_finder 시드 하나의 동시검색 군집을 조회한다 150×입력 키워드 + 50×고유 키워드(노드) keyword · gl
lm_cluster_keyword_list POST /cluster_finder/keyword_list lm_cluster_finder와 같은 동시검색 그래프에서 키워드 목록만 돌려준다(군집·관계 없음) 30×입력 키워드 + 2×반환 키워드 · 명세값 · 실측 대조 전 [가정] keyword · gl
lm_intent_finder POST /intent_finder/keyword_list 시드 키워드의 연관 검색어를 키워드 문자열 목록으로 돌려준다(지표 없음 — 지표는 lm_keyword_info로 붙인다) 30×입력 키워드 + 2×반환 키워드 · 명세값 · 실측 대조 전 [가정] keywords · gl
lm_keyword_info POST /keyword_info 키워드별 검색량·광고지표(ads_metrics) 또는 월별 시계열·의도·인구통계(all)를 조회한다 data_type별 — ads_metrics 1×키워드 · all 10×키워드 keywords · gl · data_type
lm_path_finder POST /path_finder 키워드 앞뒤로 이어지는 세션 인접 검색 경로를 조회한다(집계 행동이지 개인 여정이 아님) 50×입력 키워드 + 40×경로 안 고유 키워드 keyword · gl
lm_path_keyword_list POST /path_finder/keyword_list lm_path_finder의 경로에 등장하는 키워드 목록만 돌려준다(경로 순서·전이 없음) 30×입력 키워드 + 2×반환 키워드 · 명세값 · 실측 대조 전 [가정] keyword · gl
lm_serp POST /serp 키워드의 구글 검색결과 화면(SERP) 블록을 돌려준다 30×입력 키워드 (출력 무과금) keyword · gl
lm_trend_finder POST /trend_finder/issue_list 시드 키워드 하나 주변에서 최근 급부상한 이슈(키워드·이슈 점수·요약·출처 링크)를 돌려준다 50×입력 키워드 + 2×반환 이슈 · 빈 결과는 0(실측 1건 · 환경마다 확인) keyword · gl
lm_usage_summary GET /usage/summary 기간(from·to, YYYY-MM-DD) 동안 이 계정의 호출 수·에러율·엔드포인트별 호출 수·일별 시계열을 돌려준다 명세(v0.0.60)에 단가 없음 — 원장의 cost_detail로 확인한다 from · to
  • 결정식은 모두 «입력 단가 × 입력 수 + 출력 단가 × 출력 수»이고 단가는 명세 잠금 파일에서 온다 — 코드에 적지 않는다.
  • «실측 대조 전 [가정]»이 붙은 단가는 명세값이다. 실연결 첫 호출에서 원장의 formula_match로 확인한다.
  • lm_keyword_info의 all은 같은 세션에서 ads_metrics로 먼저 확인한 키워드에만 허용된다(2단 조회).

6. 실연결 전 체크리스트

  • LM_API_BASE에 운영 주소를 넣고 sync로 잠금 파일과 운영 명세가 같은지 확인 (종료 코드 0 · 크레딧 0) — 이번 예시는 잠금 파일로 대체했다
  • 키는 환경변수 LM_API_KEY로만 넣는다 — 코드·저장소·로그·원장에 남기지 않는다
  • 에이전트에 줄 도구 목록을 정해 도구 JSON과 런타임에 같은 목록을 준다 (path_finder는 여정이 꼭 필요할 때만)
  • 시스템 프롬프트에 system_rules.txt를 붙인다
  • 첫 실호출은 lm_keyword_info ads_metrics 1키워드(1크레딧)로 키·주소 확인
  • «실측 대조 전» 단가 도구(키워드 목록 2종 · 연관어)는 작은 limit 1회로 원장 formula_match=true 확인
  • cluster·path는 작은 limit 1회씩(예: cluster limit 10 · path limit 3)으로 응답 모양과 formula_match 확인
  • 1회 상한(1,000)·세션 예산(5,000)은 예시값이다 — 실제 계약 한도에 맞춰 사람이 정한다
  • 원장의 used_credits는 월간 누적이다 — 잔여는 계약 한도에서 따로 계산한다
  • 여러 에이전트·프로세스가 한 예산을 나누면 원장을 합쳐서 본다 (런타임은 세션 단위)

  2. 시점은 lm_meta.data_ref_month(데이터 기준월)로 말한다. 조회일이 아니다. 지연은 lm_meta.lag_months로 응답에서 읽는다(관측 1개월). 월 그레인이므로 주간 조기경보에 쓰지 않는다.
  3. volume_trend_do_not_use는 판정에 쓰지 않는다. 추세는 yoy_ex_last_month, 기저 게이트 미달(below_base_gate)은 랭킹에서 뺀다.
  4. canonical이 같은 키워드는 표기변형이다. dup_of가 있는 행은 같은 검색의 중복이라 한 번만 센다. 집계는 lm_meta.variant_groups 기준으로 하되, 그룹 볼륨은 volume_lo(하한·최댓값)와 volume_hi(상한·중복 제외 합)를 병기한다 [추정]. 한쪽만 고르거나 행을 그냥 합산하지 않는다. 순위·판정은 volume_lo 기준, volume_hi로 뒤집히면 그 사실을 적는다.
  5. lm_meta.truncated가 true이거나 null(판정 불가)이면 «더 없다»고 말하지 않는다. limit을 올리거나 수렴 판정을 보류한다.
  6. 도구가 budget_guard로 막히면 남은 예산(remaining)을 사용자에게 알리고 범위를 줄인다. 우회하지 않는다.
  7. 검색량 단위는 «건»이다(사람 수 아님). 검색은 관심 신호이지 구매가 아니다.
  8. SERP는 저장된 스냅샷이다 — lm_meta.collected_at(수집 시각)을 적고 «지금 순위»라고 말하지 않는다.
  9. 트렌드 이슈는 검색량이 아니다. 수요·추세 판정은 keyword_info로 하고, 검색량으로 확인되지 않은 이슈는 «이슈 신호만 · 검색량 미확인»으로 따로 적는다. 빈 결과는 «그 기간 매칭 없음»이라는 실측이다.
  10. [검토 전] 도구의 응답은 해석 규칙이 없다 — 수치를 판정에 쓰지 않고 사람에게 확인을 요청한다.
